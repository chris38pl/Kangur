## User-facing (What users see)

After upgrade, a **bottom toast** opens **What's New** (`/whats-new`). Full bullets in `1.0.5.json` (PL/EN). Summary vs 1.0.4:

1. **Home list index** - a new list shows on Home without pull-to-refresh, including when someone else in a shared workspace creates it.
2. **Add to an existing list** - recipe, photo (camera or gallery), and previous lists append products. History suggestions omit products already on the list (same identity, so "Pomidory" and "pomidor" count as one).

---

## Mobile - list index

- [x] Quiet refetch of `["shopping-lists", workspaceId]` and history after item add/remove, meal apply, and AI apply.
- [x] Optimistic `itemCount` bump so Home's `itemCount > 0` filter does not hide a list the user just filled in.
- [x] Home and Lists focus refetch when the index is older than ~5s (no pull spinner; Lists keeps `refetchOnMount: false`).
- [x] App foreground refreshes the active workspace index and resumable shopping sessions.
- [x] Shared workspace (`memberCount > 1`) polls that index and sessions about every 12s while the app is active. Solo workspaces do not poll.
- [x] Push with payload `LIST` or `SHOPPING` refreshes the index immediately (`SHOPPING` also refreshes resumable sessions). Preferences stay unchanged; polling covers members who have list notifications off.

---

## Mobile - add to an existing list

- [x] List screen titles say add (AI and recipe), not create. Home create sheet copy is unchanged.
- [x] Photo row offers camera or gallery, then the existing ingest on this list.
- [x] "Previous lists" uses the same proposal sheet. `POST suggest-from-history` accepts optional `listId`, excludes that list from sources, and drops items whose `toProductIdentityKey` is already on the list.
- [x] When nothing new remains, the API returns `HISTORY_ALREADY_ON_LIST` and does not reserve an AI credit or store a run.
- [x] Apply appends onto `run.listId` (sort order after the last item). It does not create a list, emit `list_created`, or send a list-created push. A run without `listId` still creates a new list.

## Release ops (when closing 1.0.5)

Do not run these while more fixes are still landing. `APP_LATEST_VERSION` is what prompts devices already on production. Set it only once a store build of 1.0.5 exists.

1. Commit remaining 1.0.5 work on `release/1.0.5` (explicit ask).
2. Merge `release/1.0.5` → `staging` (explicit ask).
3. Confirm Vercel staging: `APP_LATEST_VERSION=1.0.5`.
4. Smoke:
   - create a list (manual add, AI, meals) and return to Home without pull-to-refresh
   - second member of a shared workspace sees the new list while staying on Home
   - on an existing list, previous-list suggestions omit products already there (including a different form of the same name) and append the rest; recipe and photo append too
   - What's New toast → `/whats-new` shows 1.0.5
5. EAS preview / Closed Testing as needed.
6. Promote to `main` only on explicit ask. Then set production `APP_LATEST_VERSION=1.0.5`.
